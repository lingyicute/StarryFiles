Features

化繁为简，
但威力不减。

遵循 Material Design 规范，注重细节。底层用对的技术，上层保持克制。

Material Design，且是干净的那种

布局、对齐、间距、图标、字体——那些别人懒得修的小瑕疵，这里没有。支持自定义 UI 颜色、夜间模式与可选的纯黑主题。

开源可信

GPL-3.0 许可。把 Root 权限交给一款闭源应用令人不安，交给开源代码则心安理得。

面包屑导航

路径层级一目了然，在文件系统中任意跳转、轻松回溯。

压缩包支持

直接查看、解压与创建常见压缩格式，一步搞定不折腾。

网络存储

支持 FTP、SFTP、SMB 与 WebDAV，像本地文件夹一样浏览和管理远程文件。

Root 支持

以 Root 身份查看与管理系统文件，操作透明可审计。

Linux 感知

像 Nautilus 一样理解符号链接、文件权限与 SELinux 上下文，甚至能处理非法 UTF-8 文件名。

快速且健壮

用 NIO2 的接口形态作骨架的重新实现，通过 JNI 直达 libc 标准调用，杜绝文件管理器家族的解析 ls 顽疾。

Why StarryFiles

为什么又造一个文件管理器？

因为我喜欢 Material Design，喜欢开源，也相信「把事情做对」这件事本身值得。

01

正确的后端

以 Java NIO2 File API 作为后端，而非自创一个和 UI 纠缠不清的文件模型。解耦意味着更少的 Bug，也更容易接入新的文件系统。

02

直达系统调用

不用 java.io.File，也不解析 ls。直接绑定 Linux syscall，因而快速、可靠，能正确处理符号链接、权限与 SELinux 上下文。

03

现代的前端

基于 ViewModel 与 LiveData 构建，结构清晰、天然支持旋转，并妥善处理操作错误、文件冲突与前后台状态。
